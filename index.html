Applied AI · Voice assistant · Flagship

ARIA

A voice assistant that keeps working when the internet doesn't. Answers locally offline and escalates to the cloud only when it has to.

How it works

Voice assistants stop working the moment the internet does — useless on a student budget in Cameroon. ARIA is built around a skill router that answers locally when offline and escalates to the cloud only when it must: an Android bridge server drives Wi-Fi, flashlight, alarms and screenshots natively, a PWA control panel stays usable on any device, and DeepSeek is a pluggable upgrade, not a dependency. The result is an assistant that keeps its core skills in airplane mode.

  • Kotlin
  • Flask
  • DeepSeek

Systems · Protocol engineering

Phoney

Phone Link for Linux — notifications, file transfer and clipboard sync with your Android phone over the paired KDE Connect protocol.

How it works

The Android side ships as the stock KDE Connect app, so you never install an unknown APK. Phoney speaks the same protocol: UDP discovery on port 1716, TLS with self-signed certificates on both ends, then a certificate exchange that stores the PEM of every device you accept. Reimplementing the handshake taught me why both sides waiting on each other deadlocks a connection — and how one recv on the wrong socket survives every unit test and fails in the wild.

  • Python
  • TLS
  • KDE Connect
  • Linux

Mobile · Marketplace · Flutter

Re-kollect

A waste-collection marketplace connecting generators with collectors: role-based auth, live map pinning, and push fan-out to nearby collectors.

How it works

In many Cameroonian neighbourhoods waste collection is a cash and coordination mess — generators can't find collectors, collectors can't find work. The Flutter marketplace connects the two sides: role-based auth, a Firestore request lifecycle, live map pinning via OpenStreetMap and Nominatim geocoding, and FCM fan-out so a posted pickup reaches nearby collectors in seconds. Completion is only accepted within 50 m of the job location, and every position write lands in an append-only log as evidence.

  • Dart
  • Firebase
  • OpenStreetMap

Pulse Fit

Computer vision · Gesture control

Air Canvas

Draw in the air with hand gestures. A five-gesture mode machine driven by MediaPipe hand landmarks — no mouse required.

How it works

MediaPipe hand landmarks drive a five-gesture mode machine — draw, hover, erase, palette, clear — where the hard part wasn't tracking, it was gesture stability: filtering pinch jitter so a trembling hand doesn't spray dots across the canvas. Tuning the temporal smoothing against real webcam footage at 15fps was the whole project.

Realtime web · Party game

Who Is Most Likely To

A party game for friends: everyone joins with a room code, one question lands on every screen, votes stay secret until the reveal.

How it works

Room codes skip look-alike glyphs so they're easy to say out loud, and timed phases compute their countdown from the server clock so a phone with the wrong time still counts down correctly. Votes stay hidden until the reveal — including who skipped — and the full-screen "YOU" moment only appears on the winner's own device. It runs on Vercel with Upstash Redis and needs no card to deploy.

Notes

How I think & build

Short write-ups on decisions I'd defend, and a few I'd reverse.

Engineering

Graceful degradation is a feature, not an apology

Building for Cameroon taught me that "no internet" is a normal state, not an error state. Every product I ship now has an offline path that stays genuinely useful — from ARIA's local skill router to Pulse Fit's simulated data. If the demo dies when the Wi-Fi does, it was never finished.

Process

Ship the boring parts first

Hackathons reward the demo; production rewards the recovery. I now build error states, empty states, and the onboarding path before the shiny flow. The lesson came from Re-kollect: the features everyone remembered were the ones that worked when something upstream failed.

Building in public

What pairing over TLS actually taught me

Reimplementing the KDE Connect protocol taught me more than any tutorial: identity exchange before TLS, why both sides waiting on each other deadlocks a handshake, and how a single recv on the wrong socket survives every unit test and fails in the wild. I'm writing up the full protocol walkthrough as I go.
